# Класифікатор стратегій + онтологія моделей надійності

Репозиторій містить два шари одного методу:

1. **Класифікатор стратегій** ([П2], DOI 10.26906/SUNZ.2025.2.195-202) — фасети з доменами →
   декартів добуток (FCE) → фільтрація обмеженнями (FCE\*). Реалізація: `models/classifier.py`,
   GUI `app.py`, CLI `create_configurations.py`. Детальний опис — у `CLAUDE.md`.
2. **Онтологія моделей надійності** (гілка `ontology-project`) — надбудова над тим самим форматом
   JSON: пошарове кодування фасетів (O/M), правила-анотації, блок екземплярів, gap-матриця та
   пошук за умовами місії. Реалізація: `models/ontology.py`, нотбук `ontology_notebook.py`,
   перевірки `check_ontology.py`. ТЗ — `TZ_marimo_ontology.md`.

Шар 1 у цій гілці **не змінювався**: `models/classifier.py` та `app.py` лишилися такими, як у `main`.

## Встановлення та запуск

Python 3.9, локальний venv:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Усе запускається з кореня репозиторію (`models/` не має `__init__.py` і резолвиться як неявний
namespace-пакет, тому корінь має бути в `sys.path`).

```bash
# старий шар
python app.py                                              # PyQt5 GUI класифікатора
python create_configurations.py projects/project_swarm_of_UAV.json

# новий шар
python check_ontology.py                                   # приймальні перевірки §6.2-§6.5 ТЗ
marimo edit ontology_notebook.py                           # як нотбук
marimo run  ontology_notebook.py                           # як веб-додаток
```

Нотбук читає будь-який файл із `projects/*.json`. Класифікаторні файли [П2] теж відкриваються —
у них немає шару M та блоку `instances`, тому комірки аудиту, пошуку й експорту лишаються
порожніми. Експорт пише в `exports/` (каталог у `.gitignore`).

## Чим новий движок відрізняється від старого

- **Дедуплікації немає.** `classifier.py` схлопує валідні конфігурації за форматованим рядком
  (48 комбінацій → 42 рядки). Gap-матриця рахує клітини простору, тому новий движок працює з
  векторами; рядок формується лише для відображення. Перевірка узгодженості: новий движок на
  канонічному `project_swarm_of_UAV.json` дає 144/48/96 — саме той комбінаційний розподіл, який
  старий движок показує як 144/42/96.
- **Шар M не перебирається.** Декартів добуток будується лише по шару O; міжшарові правила дають
  для кожного валідного O-вектора *залишковий домен* кожного M-фасета. Якби M перебирався нарівні
  з O, кожна модель множилася б на кількість методів, якими її можна розв'язати.
- **Порожній залишковий домен — це суперечність у наборі правил**, а не властивість системи; такі
  вектори збираються окремо (`contradictory_configurations()`).
- **Анотації та `null` не пишуться назад у вектор**, а накопичуються окремо й застосовуються лише
  при формуванні виводу — те саме розділення, що й `null_overrides` у коміті `f42021a`.

## Відкрите питання

Крок 6 Алгоритму 1 («є-спецвипадком») **не автоматизовано** — див. TODO у `TZ_marimo_ontology.md`
§4 і в `models/ontology.py::verification_candidates`. З координат вивести «звуження» неможливо:
домени фасетів не мають відношення порядку. Наразі движок лише переносить відношення, вже записані
у файлі, і позначає результат як перелік кандидатів.
