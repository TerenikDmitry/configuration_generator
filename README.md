# Класифікатор стратегій + онтологія моделей надійності

Репозиторій містить два шари одного методу у двох **незалежних пакетах** — жоден не імпортує
інший і не читає файли іншого:

1. **Класифікатор стратегій** ([П2], DOI 10.26906/SUNZ.2025.2.195-202) — фасети з доменами →
   декартів добуток (FCE) → фільтрація обмеженнями (FCE\*). Пакет `classifier/`: движок
   `engine.py`, GUI `app.py`, CLI `create_configurations.py`, файли проєктів `projects/`.
2. **Онтологія моделей надійності** (гілка `ontology-project`) — формат, що походить від формату
   [П2]: пошарове кодування фасетів (O/M), правила-анотації, блок екземплярів, gap-матриця та
   пошук за умовами місії. Пакет `ontology/`: движок `engine.py`, нотбуки `notebook.py`
   (українською) і `notebook_en.py` (англійською), файли `projects/`. Приймальні перевірки —
   `ontology/tests/check_ontology.py`, ТЗ — `ontology/TZ_marimo_ontology.md`.

```
classifier/   engine.py  app.py  create_configurations.py  projects/
ontology/     engine.py  notebook.py  notebook_en.py  projects/  exports/ (у .gitignore)
              TZ_marimo_ontology.md  tests/check_ontology.py
```

Логіка движка класифікатора в цій гілці **не змінювалася**: `classifier/engine.py` — це
`models/classifier.py` з `main`, перенесений без правок; у `classifier/app.py` змінено лише
каталог діалогів відкриття/збереження (`classifier/projects/`).

## Встановлення та запуск

Python 3.11 (мінімум 3.10 — marimo 0.24 більше не підтримує 3.9), локальний venv:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Поточні піни: `marimo==0.24.2`, `pandas==3.0.6`, `PyQt5==5.15.11`.

Команди класифікатора запускаються з кореня репозиторію через `python -m` (пакети імпортуються
як `classifier.*`). Нотбуки й `ontology/tests/check_ontology.py` самі додають корінь до `sys.path`.

```bash
# класифікатор
python -m classifier.app                                   # PyQt5 GUI
python -m classifier.create_configurations classifier/projects/project_swarm_of_UAV.json

# онтологія
python ontology/tests/check_ontology.py                    # приймальні перевірки §6.2-§6.5 ТЗ
python ontology/tests/check_ontology.py ontology/projects/ontology_UAV_models_en.json
marimo edit ontology/notebook.py                           # як нотбук (українською)
marimo run  ontology/notebook.py                           # як веб-додаток
marimo edit ontology/notebook_en.py                        # англомовна версія
```

Нотбук показує лише файли з `ontology/projects/*.json`. Файл класифікатора движок онтології
відхиляє при завантаженні (`ValueError` з підказкою відкрити його пакетом `classifier`): режим
`null`, `rule_type: "domain"`, `allowed_values` і фасети без `id` у форматі онтології не
підтримуються (ТЗ §1.5). Експорт пише в `ontology/exports/` (у `.gitignore`).

### Англомовна версія

`ontology/projects/ontology_UAV_models_en.json` — повний переклад основного файлу з тими самими
`id`, порядком і вагами, тому дає ті самі числа (перевірено: збігаються валідність і
правило-винуватець для кожного з 12288 векторів, залишкові домени, аудит і результати пошуку).
Мову задає `meta.language` (`"uk"` за замовчуванням або `"en"`); вона визначає мову тексту, який
генерує сам движок. Керований словник (`facet_type`, статуси, типи відношень, ключ умов звуження)
приймається обома мовами — таблиця відповідностей у ТЗ §2.4.

Заповненість клітини визначається **статусом** екземпляра, а не самою наявністю запису: клітина з екземпляром статусу `gap` лишається прогалиною, бо модель описана, але не побудована (`OntologyEngine.space_summary()`).

`c4` має тип `note` і не блокує нічого. `c9`, `c10`, `c11` діють на шар M і в розбивці не
з'являються. Усі сім екземплярів `i1`–`i7` проходять аудит; порушень симетрії `mc ↔ mh` — 0.

`ontology/tests/check_ontology.py` звіряє всі ці числа з очікуваними й повертає ненульовий код, якщо щось
розійшлося (33 перевірки; станом на Python 3.11 + marimo 0.24.2 — `ALL CHECKS PASSED`).

## Чим новий движок відрізняється від старого

- **Дедуплікації немає.** `classifier/engine.py` схлопує валідні конфігурації за форматованим
  рядком (48 комбінацій → 42 рядки). Gap-матриця рахує клітини простору, тому новий движок працює
  з векторами; рядок формується лише для відображення.
- **Шар M не перебирається.** Декартів добуток будується лише по шару O; міжшарові правила дають
  для кожного валідного O-вектора *залишковий домен* кожного M-фасета. Якби M перебирався нарівні
  з O, кожна модель множилася б на кількість методів, якими її можна розв'язати.
- **Порожній залишковий домен — це суперечність у наборі правил**, а не властивість системи; такі
  вектори збираються окремо (`contradictory_configurations()`).
- **Анотації не пишуться назад у вектор**, а накопичуються окремо й застосовуються лише при
  формуванні виводу — те саме розділення, що й `null_overrides` у коміті `f42021a`.
- **Режиму `null` немає.** Незастосовність виражається значенням домену (`відсутні (m=0)` для O4,
  `відсутня` для O8), бо координатний вектор має лишатися повним — інакше відстань не визначена.

## Відкрите питання

Крок 6 Алгоритму 1 («є-спецвипадком») **не автоматизовано** — див. TODO у
`ontology/TZ_marimo_ontology.md` §4 і в `ontology/engine.py::OntologyEngine.verification_candidates`. З координат вивести «звуження» неможливо:
домени фасетів не мають відношення порядку. Наразі движок лише переносить відношення, вже записані
у файлі, і позначає результат як перелік кандидатів.
